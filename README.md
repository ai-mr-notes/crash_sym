# crash_sym

把崩溃日志里的十六进制地址翻译成 `函数名+偏移`，离线、纯 Python 标准库、不需要装工具链、不需要连设备。

## 为什么需要它

发布版固件/程序把调试信息剥掉之后，崩溃时能打出来的只有寄存器里的地址：

```
Exception:
 pc: 0x000a1b2c  lr: 0x000a3f04
caller: 0x000a4c1e
caller: 0x000b1234
```

这份地址对排查没直接用，但编译产物里有一张"函数 → 起始地址"的表。反汇编文本把它打印出来，拿它做区间查找，就能把每个地址翻成"崩在哪个函数、偏了多少字节"。

## 依赖

无。Python 3.8+ 标准库（`re` / `bisect` / `tarfile` / `argparse`）。

## 快速开始

先自检，确认环境没问题（不需要任何输入文件）：

```bash
python crash_sym.py --selftest
```

正常输出：

```
函数索引: 3 个
--- 符号化结果 ---
 pc: 0x00001412 <parse_pkt+0x12>  lr: 0x00001205 <net_poll+0x4>
caller: 0x0000100f <app_init+0xe>
caller: 0x00001207 <net_poll+0x6>
--- 命中 4 处，未命中 2 处 ---
自检: 通过
```

真实使用：

```bash
# 生成反汇编（务必用带符号的 ELF，不要用烧录的 bin）
arm-none-eabi-objdump -d firmware.elf > fw_20261018.dis

# 压缩后随版本归档，几十 MB 压到几 MB
tar czf fw_20261018.dis.tgz fw_20261018.dis

# 翻译日志
python crash_sym.py crash.log fw_20261018.dis.tgz -o 崩溃分析.md

# 全文翻译（默认只翻 pc/lr/caller/#N 这类栈帧行）
python crash_sym.py crash.log fw_20261018.dis --full
```

## 参数

| 参数 | 说明 |
|------|------|
| `log` | 崩溃日志文件 |
| `dis` | 反汇编文件，支持 `.dis` / `.dis.tgz` / `.tar.gz` |
| `-o, --out` | 输出文件，默认打印到屏幕 |
| `--full` | 翻译全文里的地址，默认只翻栈帧行 |
| `--selftest` | 内置样例自检 |

## 输出

命中的地址在原地址后面追加 ` <函数名+偏移>`，未命中的保持原样，末尾给一行命中统计：

```
 pc: 0x00001412 <parse_pkt+0x12>  lr: 0x00001205 <net_poll+0x4>
caller: 0x0000100f <app_init+0xe>

命中 4 处，未命中 2 处
```

## 实现要点

1. **索引**：正则匹配 objdump 的 `00001200 <net_poll>:` 标签行，收集全部函数起点后按地址排序。
2. **定位**：`bisect_right` 找到不大于目标地址的最后一个函数起点，区间上界是下一个函数起点，偏移 = 地址 - 起点。
3. **容错**：
   - Thumb 地址最低位为 1，查表前抹掉；
   - return address 比调用指令多走一条，落空时回退 2 / 4 字节再查；
   - 偏移超过 32KB 视为未命中，避免函数区间里的空洞被误归到前一个函数。
4. **降噪**：只翻译含 `pc` / `lr` / `caller` / `backtrace` / `#N` 的行，并且要求地址前后不粘连其他十六进制字符，防止序列号、时间戳被当成地址。

## 已知边界

- **只到函数级，不给行号。** 行号需要 `.debug_line` 段，得用 `addr2line` / `gdb`，且调试文件必须与固件严格对应。
- **内联和尾调用会让栈变短**，看不到被内联掉的中间层。
- **野指针翻不出来**：地址落在栈、堆、数据区时不属于任何函数区间，脚本保持原样输出。
- **不解释崩溃原因。** 它只回答"崩在哪"，不回答"为什么崩"。
- **反汇编文件必须与固件同版本。** 版本不一致时会翻译出"看着很像对"的错误结果，请把构建号写进文件名并在报告里注明。
